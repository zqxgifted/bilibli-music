# 界面说明

## 三个页签

### ① 配置

顶部常驻一张 **B站账号** 卡片，下面是四个子页签。

#### B站账号（顶部卡片）

| 元素 | 作用 |
| --- | --- |
| **登录状态** | 启动即自动查 `nav` 接口，显示 `● 已登录：用户名（mid｜大会员）`（绿）/ `● 未登录：SESSDATA 已过期…`（黄）/ `● 未登录：没有 cookies.txt…`（灰）。右侧「刷新状态」可重查。 |
| **粘贴新 SESSDATA** | 把浏览器里复制的值粘进来 → 点「保存并验证」。支持三种格式：Netscape 整行 / `SESSDATA=xxx;` 串 / 直接粘值本身。保存后自动重新验证并刷新状态。 |
| **怎么获取？** | 弹窗给出 F12 → Application → Cookie 的取法。 |

#### 子页签「基本」

| 字段 | 说明 | 易错点 |
| --- | --- | --- |
| **目标名** | 显示名，用于目录名、文档标题、日志 | 别带空格和斜杠 |
| **本人 mid** | 目标本人的 B 站 mid；没有本人号填 0 | 填错会让「本人号规则」套到别人身上 |
| **优先号** | 同一天多个 UP 发同一场时优先保留谁 | 选更新最快最稳的 |
| **别名正则** | 目标名 + 昵称的**正则**（多个用 `|` 分隔） | 单字别名会误命中，慎用 |
| **数据目录** | 音频、清单、缓存都放这儿 | 相对路径 = 程序目录 |
| **要跟踪的 UP 主** | 一行一个：`mid 空格 名字` | 名字要和投稿 author 一致 |
| **「裸歌名=在唱」频道 mid** | 这些号「标题是歌名就一定是目标在唱」 | **综合搬运号绝对不能放** |
| **纯搬运合集号 mid** | 整号排除 | 这类号一条投稿几小时、几十P |
| **音质 / 格式 / 并发 / API 间隔** | 下载参数 | 并发上限 4；间隔别低于 1.1 |

#### 子页签「黑白名单」

黑名单拆成**六栏明文**（每行一个词），全部直接可见可编辑：

| 栏 | 含义 |
| --- | --- |
| 通用关键词 | 换目标也成立（默认 `整活`） |
| 通用前缀 | 只判开头，**不带【】**（默认 `手描`） |
| 通用正则 | 看视频/反应类（默认 SEE 反应 2 条） |
| 专属关键词 | 人名/粉丝团/梗/综艺 |
| 专属前缀 | 同上，只判开头 |
| 除非合唱 | 命中排除，但含「合唱」二字豁免 |

白名单（命中强制收录，优先级高于黑名单）：关键词 + 前缀两栏。
人工强制判定：`force_cat1`（强制①）、`force_cat3`（强制③）、`nonsong_bv`（整支排除）。

> 铁律提示直接印在卡片底部：多P 歌回只判分P名，单P 才判标题。

#### 子页签「标题净化」

把当初处理文档的清洗规则做成**开关**，只影响文件名/显示名，不影响判定：

- 去 emoji 表情（💃🎄🔥⚡…）
- 花体字母还原（𝐍𝐈𝐆𝐇𝐓 → NIGHT）
- 去装饰符号（箭头/几何/颜文字/全角＾…）
- 去【…】标签
- 去 #N 系列号（保护「心拍数#0822」）
- 去开头标点
- 保留结尾语气符（~～；关掉则一并删）
- 额外要删的字符（自定义，如 `❤♥◆`）

底部**实时预览**：输入任意标题，立刻看到净化后的文件名结果。

#### 子页签「高级规则」

- **按 UP 的清洗规则**：一行一条 `UP名 | 删除串 | 提取正则 | 跳过词`，对应原来 `正则表达式.txt` 里「谁家的标题长什么样」那套。
- **弹幕/评论校验正则**：6 个可编辑框（显式署名 / 合作feat / 唱歌语境 / 群体企划 / 角色向 / 他人唱见名单），留空则按目标名自动拼。
- **其他判定参数**：已核实标签名、纯他人名单。

#### 底部

- **载入规则预设** —— 从 JSON 文件载入一套完整规则（账号、六层黑白名单、BV、校验正则、按UP清洗）一次性填进表单，可再编辑。预设含账号与人工标注属私有资料，由你自己选择文件。
- **载入空白模板** —— 清空成示例目标。
- **保存配置** —— 写 `config/user.json`。

### ② 流程

五个主步骤 + 两个辅助步骤。

| 按钮 | 做什么 | 注意 |
| --- | --- | --- |
| **① 抓取** | 拉各 UP 的投稿列表 + 分P 信息 | 首次**取消勾选**「增量」 |
| **② 判定** | 每条投稿判 ①/②/③，给每个 UP 生成清单 md | 看 ① 数量是否合理 |
| **③ 去重** | 两层去重 → 基底 → 下载清单 → 两份合集文档 | 打印「新增 N，替换 M」 |
| **④ 下载** | 按基底清单下载音频（断点续跑） | 已存在自动跳过 |
| **⑤ 校验** | 缺失 / 损坏 / 时长不符 | 正常应全是 0 |
| **⑥ 弹幕/评论校验** | 抓评论+弹幕，标出「确认本唱/他人唱/待核对」，写 `_verified_{mid}.json` | 跑完要重跑 ② 判定才用上 |
| **⑦ 构建歌名词典** | 从分P名抽真实歌名补进 `_songs.txt` | ① 偏少时跑；跑完重跑 ② |

辅助：**扫描**（找还有谁在切目标）、**过期文件归位**（把被替换的旧版本移到 `待删除\`）。

状态表实时显示目标、缓存数、基底歌数、清单条数、已下载数、cookies、ffmpeg 位置。

### ③ 曲库

显示去重后的基底（**每首歌一条**）。可以：

- 点「选」列勾选 → 「下载选中项」只下勾的那些
- 右键复制 BV 号 / 标题，或在 B 站打开
- 双击直接在 B 站打开

### 日志面板

底部可折叠。运行时展开能看到实时输出；日志同时写到
`<数据目录>/_脚本与数据/bilimusic.log`。

## 依赖探测

右上角「**环境自检**」会检查 ffmpeg / ffprobe：

查找顺序（对每个组件都一样）：

1. `config/user.json` 里手动指定的路径
2. 包内 `bin\` 目录
3. 系统 PATH
4. 常见安装位置（含 `D:\Library\tools\ffmpeg\bin\`）

都找不到会弹窗说明：缺什么、为什么需要、去哪下载、放到哪里。
