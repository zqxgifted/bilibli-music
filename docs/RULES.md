# 判定规则原理

本文解释「一条投稿里，目标本人是不是在唱歌」是怎么判的。
规则由真实投稿实战打磨而来，**回归测试逐条 0 差异**。

---

## 一、三类判定

| 类别 | 含义 | 处置 |
| --- | --- | --- |
| **①** | 目标本人唱 / 与他人合唱 | 收进库 |
| **②** | 疑似有目标唱 | 需要人工确认 |
| **③** | 与唱歌无关 | 不收 |

---

## 二、判定顺序（短路）

```
① 白名单命中（标题或任一分P名）        → ①   （最高优先级，可覆盖黑名单）
② 人工强制 force_cat1/2/3              → 对应类别
③ 人工标注 force_cat1 / force_non_song → 对应类别
④ nonsong_bv（人工核实「确认不是唱歌」） → ③
⑤ 搬运/合集号（整号排除）              → ③
⑥ 综合音乐号/搬运号：标题没出现目标    → ③
⑦ 开头【XXX】是别人名字                → ③
⑧ 多P 歌回（分P≈每首歌）              → ①   （整场都算）
⑨ 强非唱歌词命中                       → ③
⑩ 线下活动/vlog（标题没写《歌名》）     → ③
⑪ 「纯他人」名单命中且标题不含目标      → ③
   ──────────── 到这里按「本人号 / 归档号」分流 ────────────
本人号：强信号 → 群体企划 → 时长闸门
归档号：先看像不像唱歌，再看有没有目标名
```

### ⚠️ 铁律：黑名单只判分P名

多P 歌回只判**分P名**，单P 才判标题；合集总标题永远不参与判定。

否则一场 20 首的歌回会因为总标题含某个词被**整体排除**（真实项目误杀 10 个正常分P）。

---

## 三、本人号的判定（强信号 → 群体企划 → 时长闸门）

本人号的标题多是一句歌词或玩梗，常常**没有歌名、没有「唱」字**。
实测：171 个已知本唱里，98% 时长 40–600s，只有 39% 标题写了《歌名》，
25% 完全没有任何唱歌字眼。

所以不能靠「标题有歌名」，要靠三级：

```
强信号（引号内歌名 / 强署名 / 翻唱·合唱·献唱 / ⚡歌名⚡）   → ①
「歌ってみた/替え歌」且无目标署名                          → ③（早年搬运他人）
人工校验标签 = verified 且置信度 ≥ 0.6                      → ①
引号内歌名 / 整条标题即歌名 / 强信号系列名（串烧·连唱…）   → ①
群体企划（拜年祭·十人合唱…）：有歌名 或 时长 60–330s       → ①，否则 ②
时长 60–330s 且不是杂谈词                                  → ①
时长 ≤640s 且不是杂谈词                                    → ②（等人工）
其余                                                       → ③
```

> 时长上界为什么是 330 而不是 640：实测 330–640s 共 30 条投稿，其中真歌只有 8 条，
> 其余是游戏实况/漫展/vlog。这段保留在 ② 等人工确认。

---

## 四、归档号的判定（二创/切片号）

```
标题不像唱歌（游戏/直播/反应/杂谈/搬运合集/有声书…）  → ③
标题含目标名：
    引号内歌名 / 强署名 / 翻唱·合唱 / ⚡歌名⚡        → ①
    已知歌名 + 「唱/歌」字样                          → ①
    其余                                            → ②
标题不含目标名：
    人工校验标签可信                                → ①
    标签 unknown 且标题含「歌切/歌回」              → ①
    标题命中已知歌名                                → ①
    其余                                            → ②
```

---

## 五、歌名怎么来的

```
有分P名  → 分P名 = 歌名（先清「01.」序号、清「（xx视角）（完整版）」修饰）
分P名无意义（P1/正片/纯享版/Vocal：xx）→ 回退总标题抽歌名
单P      → 总标题抽《》/「」/“”里的曲名
          → 抽不到试「唱XXX」
          → 再抽不到取去号主前缀后的前段
后处理   → 去序号 / 去「<目标名>-」前缀 / 去修饰括号
          → 去「纯享版|完整版|片段|cut|cover|版」后缀 / 去标点 / 转小写
人工     → manual_disp（显示名）/ manual_key（去重键）最优先
```

> ⚠️ **归一化时必须先去掉 emoji 和零宽字符**。少了这步，「❤️萌妹」和「❤萌妹」
> 会算成两首歌，去重时互相顶替，磁盘上就会多出一堆重复文件。

## 六、黑白名单

### 优先级

```
白名单（include_* / force_cat1） > 黑名单（exclude_* / force_non_song） > 默认判定
```

同一单元同时命中黑白名单时，**白名单胜**。这是刻意的：
白名单是「我明确要」，黑名单是「规则认为不要」。

### 分层：通用 vs 专属

| | 通用层（`*_generic`） | 专属层（`*_project`） |
| --- | --- | --- |
| 判据 | **换任何目标都成立**的「形式特征」 | 只在当前目标语境成立的「内容特征」 |
| 典型 | `整活`、`手描`、SEE 反应类 | 粉丝团名、合作方、专属梗、参加的综艺 |
| 换人时 | **整段照搬**，不用改 | 必须清空重写 |

判断口诀：**「这条规则换个歌手还成立吗？」** 成立 → 通用层；只在某人家成立 → 专属层。

### 作用范围（三条边界，错了会误伤整场）

1. **多P 歌回只看分P名，单P 才看标题**；合集总标题永远不参与判定。
2. **子串匹配忽略空格**：`神 人 最 多 的 一 集` 也能被 `神人最多的一集` 命中。
3. **前缀匹配先剥掉开头的符号/emoji**：`【粉丝团名】xxx`、`（粉丝团名）xxx` 都能被 `粉丝团名` 命中
   —— 所以关键词**不要带【】**，带了反而匹配不到。
   **前缀只判开头、句中不判**：想连句中一起排，用关键词层（但注意别误伤真歌名）。

---

## 七、标准操作五步（加/删一条歌）

```
① 改配置：关键词类改 config/user.json 或 GUI「目标」页；BV 类改 manual_labels.json
② 跑「② 判定」     → 看 ①②③ 数字变化是否符合预期
③ 跑「③ 去重」     → 看「黑名单排除 N 个单元」和「基底条数」变化
④ 跑「④ 下载」     → 白名单新增的歌、以及被拉黑后换上来的新基底都会被补下
⑤ 跑「⑤ 校验」     → 缺失 / 损坏 / 时长必须都是 0
```

> ⚠️ **换入效应**：把某条被错收的杂谈/切片拉黑后，去重可能把同场被压住的另一条切片
> **推上来当基底**，这条往往磁盘上没有音频。所以第 ④ 步不能省，
> 跑完再 ⑤ 确认「缺失 0」。
