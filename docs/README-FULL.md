# B站歌下载工具箱 · bilimusic（完整包）

> 把「某个歌手 / 某个 UP 的二创圈」在 B 站唱过的歌，抓下来 → 判是不是本人在唱 →
> 去重成单曲 → 下载成标签干净的本地音频库，并持续增量维护。
>
> **完整包自带 ffmpeg / ffprobe**，解压即用，不需要另外装。

---

## 一、还需要准备什么

只有一样：**cookies.txt**（可选但强烈建议）。

| 项目 | 说明 |
| --- | --- |
| **cookies.txt**（可选） | Netscape 格式，含一行 `SESSDATA`。<br>不放也能用，但拿不到大会员音质（最高 192K），且空间投稿列表更容易被风控。<br>格式见 `cookies.txt.example`。 |

## 二、五分钟上手

1. 双击 `bilimusic.exe`（或 `start.bat`）。
2. 到「**配置**」页填（顶部「基本」子页签）：
   - **目标名**：显示名，如 `目标名`
   - **别名正则**：目标名/昵称的**正则**，如 `目标名|别名1|别名2|栗`
   - **数据目录**：音频和清单放哪儿（默认 `./workspace`）
   - **要跟踪的 UP 主**：一行一个，`mid 空格 名字`，例：`12345678 目标名`
3. 点右上角「**保存配置**」。
4. 到「**流程**」页，按顺序点：
   - `① 抓取` —— 首次**取消勾选**「增量」；之后勾选（只拉新投稿）
   - `② 判定` —— 判 ①本人在唱 / ②疑似 / ③无关
   - `③ 去重` —— 两层去重 → 基底 → 下载清单
   - `④ 下载` —— 按基底清单下载音频
   - `⑤ 校验` —— 检查缺失 / 损坏 / 时长
5. 「**曲库**」页可以查看结果、勾选要下的条目单独下载。
6. 「**配置 → B站账号**」卡片实时显示登录状态，可直接粘贴新 SESSDATA 更新 cookies；
   「**配置 → 黑白名单 / 标题净化 / 高级规则**」把全部判定与清洗规则做成明文可编辑项。

## 三、目录结构

程序目录下会生成：

```
workspace\
├── _脚本与数据\        缓存、清单、基底、日志（都是 json/txt，可随时删了重跑）
├── _文档\              两份合集文档 + 每个 UP 一份三分类清单
├── _BILI<目标名>\       本人投稿的音频
├── _BILI<目标名>up歌切\ 二创 UP 的音频
└── 待删除\             被替换下来的旧版本（确认后清空）

bin\
├── ffmpeg.exe
└── ffprobe.exe
```

## 四、遇到问题先看这里

| 现象 | 原因与处理 |
| --- | --- |
| 抓取报 412 / -352 / -799 | B 站**按号限流**，不是 IP 被封。等 30–60 分钟再跑那一个号。**下载不受影响**，可以先跑 `④ 下载`。 |
| 大量 412 且提示 SESSDATA 过期 | 换一份新的 `cookies.txt`。程序已能自动识别并提示。 |
| `① 判定` 数量明显偏少 | 补 `_脚本与数据\_songs.txt`（歌名词典）、扩 `别名正则`、把该号加进「裸歌名=在唱」频道。 |
| 别人的歌混进来 | 该号不该在「裸歌名=在唱」频道；纯搬运号要单独排除。 |
| 某几条判错 | 在 `manual_labels.json` 里写 `force_*`，**别改判定规则**。 |
| 改完发现曲库条数不对 | 跑完 `③ 去重` 要再跑 `④ 下载`（新基底往往还没有音频）。 |

更多细节见 `docs/` 目录。
