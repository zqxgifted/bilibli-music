# bilimusic · B站歌下载工具箱

> 把「某个歌手 / 某个 UP 主 / 某个二创圈」在 B 站唱过的歌，
> 抓下来 → 判定是不是本人在唱 → 去重成单曲 → 下载成标签干净的本地音频库，
> 并持续增量维护。
>
> **这个工具是通用的**：目标是谁、跟哪些号、什么该收什么该排除，全部由你在界面上填。
> 程序自带的规则是**空白模板**，不含任何特定人物、账号或私人口味。

---

## 它能做什么

```
① 抓取   拉各 UP 的投稿列表 + 分P 信息（WBI 签名 + 限速 + 风控退避）
   ↓
② 判定   每条投稿判 ①本人在唱 / ②疑似 / ③无关（规则 + 人工标注）
   ↓
③ 去重   第一层：同一场演唱只留一条 → 第二层：每首歌只留最新演唱 → 基底
   ↓
④ 下载   按基底清单下载音轨，无损封装成 m4a（断点续跑）
   ↓
⑤ 校验   缺失 / 损坏 / 时长不符
⑥ 弹幕/评论校验   抓评论+弹幕，标出「确认本唱 / 他人唱 / 待核对」
⑦ 构建歌名词典    从分P名抽真实歌名，补进 _songs.txt
```

输出：两份 Markdown 歌单 + 每首一个音频文件（`歌名_BV号_p分P号.m4a`，内嵌标题/UP/来源）。

## 快速开始

### 用发布包（推荐）

1. 解压 `bilimusic_v*_win-x64.zip`（自带 ffmpeg，解压即用）
2. 双击 `bilimusic.exe`
3. 到「**配置 → 基本**」填：
   - **目标名**：要下载谁（显示名）
   - **别名正则**：目标名 + 昵称，多个用 `|` 分隔，例：`某某|某某宝`
   - **数据目录**：音频和清单放哪儿（默认程序目录下 `workspace`）
   - **要跟踪的 UP 主**：一行一个，`mid 空格 名字`，例：`12345678 某UP名`
4. 点「**保存配置**」
5. 到「**流程**」页依次点：① 抓取 → ② 判定 → ③ 去重 → ④ 下载 → ⑤ 校验

> mid 是 B 站空间号，打开 `space.bilibili.com/<这串数字>` 就是那个 UP 的投稿页。

### 从源码跑

```powershell
cd bilimusic
python gui/launcher.py
```

需要 Python 3.10+ 与 ffmpeg（或用 `bin\ffmpeg.exe`）。

## 界面

| 页签 | 内容 |
| --- | --- |
| **配置** | 顶部 **B站账号** 卡片（显示已登录/未登录、可直接粘贴 SESSDATA 更新）；四个子页签：**基本** / **黑白名单** / **标题净化** / **高级规则** |
| **流程** | 七个步骤按钮 + 状态表 + 扫描、过期文件归位 |
| **曲库** | 去重后的基底（每首歌一条），可勾选单独下载 |

### 关键配置都在界面上

- **B站账号**：实时显示 `● 已登录：用户名（mid｜大会员）`；粘贴 SESSDATA 点「保存并验证」即刻换 cookie（三种粘贴格式都认）。登录能拿更高音质、抓取更稳。
- **黑白名单**：六栏明文可编辑（通用关键词/前缀/正则 + 专属关键词/前缀 + 除非合唱），外加白名单与人工强制 BV。
- **标题净化**：emoji / 花体还原 / 装饰符号 / 【】标签 / #N 系列号 / 开头标点 / 结尾语气符 / 额外字符，每个一个开关，**带实时预览**。
- **高级规则**：按 UP 的清洗规则、弹幕校验正则、纯他人名单。

> 改完点右下角「保存配置」，写进 `config/user.json`（该文件不进 git）。

## 目录结构

```
bilimusic/
├── core/               核心逻辑（无 GUI 依赖，可当库用）
│   ├── config.py       分层配置
│   ├── naming.py       文件名 / 歌名清洗
│   ├── rules.py        判定规则引擎
│   ├── bili_api.py     B站接口（view / playurl / 空间列表 / 搜索）
│   ├── fetcher.py      抓投稿 + 歌名词典构建
│   ├── dedup.py        两层去重 + 基底
│   ├── downloader.py   下载 + 校验 + 过期文件归位
│   ├── verify.py       弹幕/评论校验
│   └── pipeline.py     编排
├── gui/                tkinter 界面
├── config/             defaults.json（默认）/ user.example.json（模板）
├── docs/               GUI / CONFIG / RULES / API / PITFALLS
└── manual_labels.example.json
```

运行后在数据目录生成：

```
workspace/
├── _脚本与数据/        缓存、清单、基底、日志
├── _文档/              两份歌单 + 每个 UP 一份三分类清单
├── _BILI<目标名>/       本人投稿的音频
├── _BILI<目标名>up歌切/ 其他 UP 的音频
└── 待删除/             被替换的旧版本（删除 = 移动，可后悔）
```

---

## 三条铁律

1. **删除 = 移动**。一律移到 `待删除\`（同盘重命名，可后悔），别直接删。
2. **黑名单只判分P名**，多P 歌回绝不判总标题（否则整场被误杀）。
3. **基底是唯一真相**：`基底条数 == 唯一键数 == 磁盘文件数`，差一个说明流程漏了一步。

## 遇到问题

| 现象 | 处理 |
| --- | --- |
| 抓取报 412 / -352 / -799 | B 站按号限流，等 30–60 分钟再跑那个号。**下载不受影响**，可先跑 ④。 |
| 提示 SESSDATA 过期 | 到「配置 → B站账号」粘贴新的。仍可下载，只是最高 192K。 |
| ① 数量明显偏少 | 跑「⑦ 构建歌名词典」；扩「别名正则」；把该号加进「裸歌名=在唱」频道。 |
| 别人的歌混进来 | 该号不该在「裸歌名=在唱」频道；纯搬运号填进「纯搬运合集号」。 |
| 某几条判错 | 在 `manual_labels.json` 里写 `force_*`，**别改判定规则**。 |
| 改完曲库条数不对 | 跑完 ③ 去重要再跑 ④ 下载（新基底往往还没音频）。 |
